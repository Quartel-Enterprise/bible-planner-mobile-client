# Store listing metadata

The copy on the Google Play and App Store listings — title, subtitle, keywords, descriptions —
is **versioned here, not typed into the consoles**. Both release lanes upload it, so the repo is
what the listings say. Edit the copy in a pull request; a change made in the Play Console or App
Store Connect survives only until the next release overwrites it.

This is the sibling of [Store listing screenshots](store-listing-screenshots.md), which covers the
images. The screenshots are generated from the app's real screens; the copy below is written by
hand.

## Why it lives in the repo

It didn't, until 2.8.2 — and all six descriptions drifted two versions behind the app without
anyone noticing. They still told shoppers the app "does not include the actual Bible text" long
after the reader, the highlights and the offline translations shipped, and the App Store copy
still promised that nothing left the device long after accounts and sync did. Nothing catches
that, because nothing reviews a console field. A `.txt` file in a diff gets read.

## The layout

Each store gets the directory shape its fastlane action expects.

```
fastlane/metadata/
    android/<locale>/               # Google Play, uploaded by `supply`
        title.txt                   # 30 characters
        short_description.txt       # 80 characters
        full_description.txt        # 4000 characters — indexed by Play search
    <locale>/                       # App Store, uploaded by `deliver`
        name.txt                    # 30 characters
        subtitle.txt                # 30 characters — indexed
        keywords.txt                # 100 characters — indexed
        description.txt             # 4000 characters — NOT indexed, conversion only
```

The locales are the ones each listing actually has, and they are the same lists
`build.gradle.kts` stages screenshots into:

| Store | Locales |
| -- | -- |
| Google Play | `en-US`, `pt-BR`, `es-419`, `es-ES`, `es-US` |
| App Store | `en-US`, `pt-BR`, `es-ES`, `es-MX` |

Spanish is written once and copied across that store's Spanish locales, the same way the release
notes are ([`Fastfile`](../fastlane/Fastfile)). Keep them identical unless a locale genuinely
needs different wording.

## What is generated and what is authored

`fastlane/metadata/` holds both, so `.gitignore` names the generated paths rather than the
directory:

| Path | Origin |
| -- | -- |
| `android/<locale>/{title,short_description,full_description}.txt` | authored, versioned |
| `<locale>/{name,subtitle,keywords,description}.txt` | authored, versioned |
| `<locale>/release_notes.txt` | generated per release from the in-app release notes JSON |
| `android/<locale>/changelogs/<versionCode>.txt` | generated per release, same source |
| `android/<locale>/images/` | generated by `./gradlew stageStoreScreenshots` |

`stageStoreScreenshots` wipes only the `images/` subdirectories, so it never touches the copy
next to them.

## Editing the copy

Character limits are hard: Google Play rejects the upload, and App Store Connect rejects the
metadata at submit time. **Count before you commit** — accents count as one character each:

```bash
awk '{ printf "%s: %d\n", FILENAME, length($0) }' fastlane/metadata/*/subtitle.txt
```

Three rules that are easy to get wrong:

- **Play indexes the full description; the App Store does not.** Play copy should carry the
  words people search for, repeated naturally. App Store copy is read, not searched — only its
  first three lines are visible before "more", and search is fed by `name`, `subtitle` and
  `keywords` instead.
- **Apple's keyword field is not a phrase list.** No space after the comma, singular only (Apple
  matches plurals), and never a word already in `name` or `subtitle` — Apple combines terms
  across the three fields, so a word repeated is a word wasted. Skip "app", the category name and
  the developer name too.
- **Never describe a feature the app does not have**, and re-read the copy whenever a feature
  lands or goes away. Bible translations in particular are listed by name; the catalogue is the
  `bible/` prefix of the Supabase `content` bucket, one `metadata.json` per version, and it grows
  without any code change here.

## How it ships

Both are part of the normal release, described in [Release process](release-process.md):

- **Google Play** — the `android upload` lane runs `upload_to_play_store` with
  `skip_upload_metadata: false`, so the listing goes up with the AAB.
- **App Store** — the `ios upload` lane runs `upload_to_app_store` against
  `fastlane/metadata/`, which carries the listing copy and the staged "What's New" together.
  `skip_metadata` is tied to whether the notes could be staged, so a release that fails to build
  its notes leaves the listing alone as well.

Neither lane has a copy-only mode: the listing updates when a version ships. To change the copy
between releases, edit it in the console *and* land the same change here, or the next release
will revert it.
